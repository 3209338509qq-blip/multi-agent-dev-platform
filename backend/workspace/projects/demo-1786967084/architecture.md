# 大学生班费管理系统 - 系统架构文档

## 1. 概述
本系统旨在为大学生班级提供一个透明、高效的班费管理平台。核心功能包括班级与成员管理、班费收支记录、财务报表查看以及简单的审核流程。系统采用经典的**前后端分离**架构。

## 2. 技术栈
- **后端**: Python 3.12, FastAPI, SQLAlchemy 2.0, Uvicorn (ASGI 服务器)
- **前端**: 单文件 HTML (内嵌 CSS 和 JavaScript)，使用 Bootstrap 5 构建响应式界面，原生 Fetch API 与后端通信。
- **数据库**: 开发/测试环境使用 SQLite；生产环境建议使用 PostgreSQL。数据库迁移工具 Alembic 可按需引入。
- **其他依赖**: Pydantic (数据校验与序列化), Pytest (测试框架)

## 3. 设计原则
- **模块化**: 后端代码按功能拆分为 `routers` (路由/视图), `schemas` (数据模型), `crud` (数据库操作), `models` (ORM 模型) 等模块，职责清晰。
- **RESTful API**: 所有功能通过统一的 RESTful API 对外暴露，便于前端及未来第三方客户端集成。
- **数据一致性**: 关键业务逻辑通过数据库事务保证。
- **可配置性**: 数据库连接等关键参数通过配置文件管理，易于环境切换。

## 4. 核心流程
1.  **班级与成员初始化**: 班委在系统中创建班级，并导入或添加成员信息。
2.  **收支记录**: 任何成员（经授权）可提交一笔收入（如班费收取）或支出（如活动采购）。记录时关联操作人和可能的相关成员。
3.  **审核流程**: 每一笔收支记录初始状态为“待审核”(PENDING)。班费管理员或指定审核员可将其更新为“已通过”(APPROVED)或“已驳回”(REJECTED)，并可添加审核意见。
4.  **财务查询与报表**: 所有成员可随时查看班级的收支明细列表，并可通过 `/summary` 接口实时获取总收入、总支出和当前余额的汇总数据。

## 5. 目录结构说明
（见上文 `directory_structure` 字段）
- `app/`: 核心应用代码。
- `app/main.py`: FastAPI 应用的创建、路由挂载和启动事件。
- `app/database.py`: 初始化数据库引擎、会话工厂和 ORM 基类。
- `app/models/`: 定义 SQLAlchemy 模型，对应数据库表。
- `app/schemas/`: 定义 Pydantic 模型，用于 API 请求体验证和响应体序列化。
- `app/routers/`: 定义 API 路由，每个文件对应一个资源模块。
- `app/crud/`: 封装数据库的增删改查操作，被路由调用。
- `static/index.html`: 完整的前端单页面应用文件。

## 6. 部署与扩展
- **本地开发**: 直接运行 `uvicorn app.main:app --reload`，数据库为项目内的 `sql_app.db` 文件。
- **生产部署**: 可使用 Docker 容器化部署，配置环境变量以使用 PostgreSQL。Nginx 可作为反向代理。
- **扩展性**: 系统设计保持开放，未来可轻松扩展：
    - **用户认证**: 添加 JWT 认证中间件，区分不同角色权限。
    - **更丰富的前端**: 将 `index.html` 替换为 React/Vue 应用，复用现有 REST API。
    - **文件上传**: 支持上传发票、收据照片，并关联到收支记录。
    - **预算管理**: 在班级或分类维度引入预算设置和预警。

## 7. 测试策略
- 使用 `pytest` 为每个 API 路由编写集成测试。
- 测试数据库使用独立的 SQLite 文件，并在每个测试后清理数据。
- 测试重点覆盖：API 响应状态码、返回数据结构、业务逻辑正确性（如余额计算）、输入验证。
